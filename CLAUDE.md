# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

AgenCoil is a multiplayer slither.io-style arena: Canvas 2D rendering, a local simulation per browser, and a full-mesh WebRTC P2P layer for other players. Bots always populate the arena, run by whichever linked client is the elected host, so the game feels full even with one player.

The repo was exported from the Grok App Builder template (`package.json` name is `app-builder-workspace`). `AGENTS.md` is that platform's sandbox contract. Its rules about `/workspace`, `startup.sh`, the live preview proxy, `imagine_*` tools and skills under `.grok/` only apply inside that sandbox. `startup.sh` does `cd /workspace`, so it will not run here. The parts of `AGENTS.md` that still matter for this checkout are listed under "Template invariants" below.

## Commands

Node 22 is the target. `node_modules` may be absent in a fresh checkout; run `npm install` first.

```bash
npm run dev            # Vite dev server on 0.0.0.0:8080 (strictPort)
npm run build          # vite build (Vercel/nitro preset) then npm run db:migrate
npm run typecheck      # tsc --noEmit (covers src/ and server/, checkJs on)
npm run lint           # eslint .
npm run format         # prettier --write . (printWidth 100, double quotes)
npm test               # all script tests + the three TS unit tests
```

Always start Vite through the npm scripts. They wrap Vite in `scripts/with-app-env.mjs`, which merges `VITE_*` keys from `.grok/app-env.json` into the environment so dev, build and preview agree on `VITE_AUTH_ENABLED`. `npm run check:auth` verifies that agreement against a running dev server.

Running a single test:

```bash
node --test scripts/preview.test.mjs
node --experimental-strip-types --test src/lib/auth/sign-in-gate.test.ts
```

Tests are plain `node --test`. Script tests live beside their module as `scripts/*.test.mjs`; the TS tests are the three files named in the `test` script in `package.json` (there is no glob for TS tests, so add new ones to that script).

Built-output preview: `npm run preview:restart` serves the last build on `127.0.0.1:8081`. `scripts/preview.mjs` finds the port owner via `/proc`, so it is Linux only. Without `DATABASE_URL` the built server falls back to PGLite, whose data file is not in the Vercel function bundle, so the first `/api/rtc` poll crashes the preview. Set a placeholder such as `DATABASE_URL=postgres://nobody@127.0.0.1:1/none` to smoke the built client; signaling then returns 500 and the game runs in local mode. `scripts/browser-smoke.mjs` (Playwright) only accepts output paths under `/workspace`, so it is sandbox only as written. Playwright browsers may need `npx playwright install chromium-headless-shell` once.

`npm test` currently fails 16 script tests on a fresh checkout because they read `.grok/skills/*` files that only exist in the sandbox. That is the baseline, not a regression signal. `npm run lint` has one pre-existing error in `src/lib/app-data/client.server.ts`.

`src/routeTree.gen.ts` is generated by the TanStack router plugin on dev/build and is gitignored. If typecheck complains it is missing, run `npm run dev` or `npm run build` once.

## Architecture

### Routes

- `src/router.tsx` exports `getRouter()` (named export, required by the TanStack Start plugin).
- `src/routes/__root.tsx` is the document shell. It mounts `PreviewHostBridge` and `AuthProvider`.
- `src/routes/index.tsx` renders `CoilApp`.
- `src/routes/api/rtc.ts` is the only API route. It lazily imports `signaling.server.ts` and forwards GET and POST.

### Game (`src/game/`)

Four layers, each a single file:

- `model.ts`: tuning constants (arena radius, speeds, tick rate, net interval, interpolation delay, bot cap, chase orb count), shared types (`Snake`, `Food`, `Camera`), banded skins, and pure helpers that derive radius, length, turn rate, boost drain, zoom and point spacing from mass. `Food.k` is the orb kind: 0 natural, 1 boost trail, 2 remains of a dead snake, 3 chase orb.
- `world.ts`: the simulation. `World.step()` clears and refills `eats` and `deaths` each tick, moves the local player and (only when `host` is true) the bots, pulls nearby orbs toward every head (the magnet), moves chase orbs away from heads, then resolves eating, collisions and culling. Bots respawn on a timer up to `desiredBots`. Food lives in a spatial hash grid keyed by cell; `forEachFoodIn` is the query the renderer and the bots use. Snakes are path-history point lists whose last point is always the head; a new point is committed once the head is one spacing from the previous committed point. Remote snakes are upserted whole each frame via `upsertRemote`.
- `engine.ts`: `CoilEngine` owns the canvas, input (mouse or WASD aim, click, space or shift to boost, wheel to zoom, touch drag steers without boosting), a fixed 60 Hz tick loop capped at two steps per frame, camera, particles, HUD state published through `subscribe()`, and all networking glue. Phases are `menu`, `play`, `dead`. `window.__coil` exposes live debug counters (points, bots, deaths, peer states) used by the Playwright checks.
- `render.ts` and `audio.ts`: Canvas 2D drawing (`Renderer`, `desiredZoom`) and a WebAudio synth (`GameAudio`). No asset files; everything is drawn in code. Bodies are drawn as shaded disc sprites placed by distance walked along the path, so a subsampled remote body looks the same as a local one. The background is a hex tile used as a canvas pattern.

Collision rules match slither.io: your head touching any other body or head kills you, both heads die on a head-on hit, the rim kills without leaving remains, and remains are worth most of the dead snake's mass.

`src/components/coil-app.tsx` is the whole UI. It creates one `CoilEngine` on mount, feeds it the P2P handle through `engine.setNet()`, and renders the menu, HUD (length, rank, kills, top-10 leaderboard), the touch boost button, and the death card over the canvas. Nickname, skin and mute are persisted in `localStorage` under `agencoil-*` keys.

### Multiplayer model (read this before touching netcode)

The game is client-authoritative by design. Each browser simulates only its own snake. There is no server tick.

- Every client broadcasts a snapshot of its own snake at `NET_INTERVAL` (18 Hz). Receivers buffer snapshots and render them `INTERP_DELAY` ms in the past (`interpRemotes`).
- Host election is deterministic: the lexicographically smallest id among this client and its *connected* peers is host. Roster entries that never reached `connected` are ignored, so a stale tab cannot silence the arena. Only the host runs bot AI and broadcasts bot snapshots; non-hosts call `clearBots()`, and a newly promoted host respawns a full bot set at once. Bot ids are prefixed `b-`, which is how receivers tell bots from players.
- A client detects its own death locally and broadcasts a death message carrying the pellets it dropped. The host does the same for bots. Receivers remove the snake and add the pellets.
- Wire messages are small objects keyed by `t`: `s` (player snake), `b` (bot snake), `d` (death). Point lists are packed as flat number arrays.
- Peers that go silent for 2.5 s or drop out of the roster are pruned.

### P2P transport (`src/lib/multiplayer/`)

- `p2p.ts`: `P2PRoom`, one `RTCPeerConnection` per remote peer with two data channels, `state` (unreliable) and `reliable`. Uses the perfect-negotiation pattern; the polite peer is the smaller id. Polls `/api/rtc` fast (400 ms) while connections form and slowly (2 s) once idle, with stall watchdogs and a bounded number of recovery attempts.
- `use-p2p-room.ts`: React hook. Peer id and name are captured once on mount so re-renders never tear the mesh down. It owns the shard index; changing the room string leaves one mesh and joins another.
- `signaling.server.ts`: the rendezvous relay. The first GET poll (`since=0`) is the join; later polls heartbeat and drain the inbox. Only SDP and ICE pass through here; game traffic never touches the server. It creates `webrtc_peers` and `webrtc_signals` with `CREATE TABLE IF NOT EXISTS` on first use rather than through migrations. Rows expire by TTL and are pruned on joins and a small fraction of polls.

Arena: there is one public arena (`agencoil-arena`), no rooms. Because the mesh is full-connect, the hook shards it invisibly: a newcomer whose first roster already shows `capacity` (8) other peers moves to `agencoil-arena-1`, then `-2`, and so on. Peers that settled in a shard stay there. STUN servers can be overridden with `VITE_STUN_URLS` (comma separated).

### Database (`src/lib/db.ts`)

`getSql()` returns a small shared SQL surface (tagged template or `.query(text, params)`) backed by Neon through `pg` when `DATABASE_URL` is set, otherwise an embedded PGLite instance. Init state is memoized on `globalThis` so dev HMR cannot open two pools. Result types are normalized so both backends return the same JSON-safe shapes (int8 to number, date to `YYYY-MM-DD`).

Migrations: `migrations/*.sql` at the top level only, applied in order and recorded in `_migrations`. The read is non-recursive, so `migrations/auth/0001_auth.sql` (Better Auth schema) is opt-in and currently not applied. `npm run build` runs `scripts/migrate.mjs` against `DATABASE_URL` and skips when it is unset. AgenCoil has no migrations of its own; the signaling tables are the only schema and they self-create.

### Template invariants

These come from `AGENTS.md` and still hold for this repo:

- Auth is OFF for this app. There is no login route, and nothing imports `authMiddleware` or `requireUserId`. Do not add sign-in unless the feature genuinely needs accounts. `src/lib/auth/` and `src/lib/app-data/` are pre-wired template code kept for the platform, not game code.
- Keep `vite.config.ts` as is: dev on `0.0.0.0:8080`, preview on `127.0.0.1:8081`, the build-only nitro plugin with `serverDir: "./server"`, `authPopupPlugin()` before `tanstackStart()`, and `grokPwaPlugin()`.
- Do not delete or rewrite `public/__grok/`, `server/`, or `scripts/grok-pwa-*`. App server routes go in `src/routes/`, never in `server/`.
- Never put `og:*` or `twitter:card` meta in `__root.tsx`; the PWA injector owns those. OG identity lives in `src/lib/og/site.json` and `public/og.jpg`.
- Keep `<PreviewHostBridge />` and `<AuthProvider>` in the root shell.
- Never create a `.env` file. Only `VITE_`-prefixed vars reach the browser.
- The deploy target is Vercel. Avoid runtime filesystem writes and server-only Node APIs at module import time.

## Styling

Tailwind v4. Design tokens are declared in `@theme` in `src/styles.css` (`bg`, `surface`, `elevated`, `fg`, `muted`, `subtle`, `line`, `accent`, `accent-fg`, `danger`, font `Outfit`). Use those token classes (`bg-surface`, `text-muted`, `border-line`) rather than raw palette colors so the UI stays coherent with the canvas art. Overlay elements that must receive pointer events while the game runs carry `data-ui`; the engine ignores pointer events originating there.
