# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

AgenCoil is a multiplayer slither.io-style arena. The game presents itself to players as "snek" (title, menu wordmark, share text, OG title in `src/lib/og/site.json`); the repository, Vercel projects, server, database tables and localStorage keys keep the AgenCoil name. A Canvas 2D client talks to an authoritative Node WebSocket server (`game-server/`) that owns the world, runs the bots and judges collisions. The client predicts its own snake, interpolates everyone else, and falls back to an offline arena with local bots when the server is unreachable.

The repo was exported from the Grok App Builder template (`package.json` name is `app-builder-workspace`). `AGENTS.md` is that platform's sandbox contract. Its rules about `/workspace`, `startup.sh`, the live preview proxy, `imagine_*` tools and skills under `.grok/` only apply inside that sandbox. `startup.sh` does `cd /workspace`, so it will not run here. The parts of `AGENTS.md` that still matter for this checkout are listed under "Template invariants" below.

## Commands

Node 22 or newer. `node_modules` may be absent in a fresh checkout; run `npm install` at the root and in `game-server/`.

```bash
npm run dev            # Vite dev server on 0.0.0.0:8080 (strictPort)
npm run build          # vite build (Vercel/nitro preset) then npm run db:migrate
npm run typecheck      # tsc --noEmit (covers src/ and server/, checkJs on)
npm run lint           # eslint .
npm run format         # prettier --write . (printWidth 100, double quotes)
npm test               # all script tests + the three TS unit tests
npm run e2e            # Playwright end-to-end suite (boots its own servers on 8198/8199)

cd game-server
npm run dev            # bundle with esbuild and run the arena on ws://localhost:8090/api/ws
npm run typecheck      # tsc for the server (it type-checks the shared src/game files too)
npm run build:vercel   # what Vercel runs: writes a Build Output API bundle to .vercel/output
```

Always start Vite through the npm scripts. They wrap Vite in `scripts/with-app-env.mjs`, which merges `VITE_*` keys from `.grok/app-env.json` into the environment so dev, build and preview agree on `VITE_AUTH_ENABLED`. `npm run check:auth` verifies that agreement against a running dev server.

To play against a local server: `VITE_GAME_SERVER=ws://127.0.0.1:8090/api/ws npm run dev`. Without the variable the client uses the production server (`defaultServerUrl()` in `src/game/net.ts`).

Running a single test:

```bash
node --test scripts/preview.test.mjs
node --experimental-strip-types --test src/lib/auth/sign-in-gate.test.ts
```

Tests are plain `node --test`. Script tests live beside their module as `scripts/*.test.mjs`; the TS tests are the three files named in the `test` script in `package.json` (there is no glob for TS tests, so add new ones to that script).

`npm run e2e` is the suite that matters for the game. `e2e/world.test.mjs` bundles the shared simulation with esbuild and checks the collision rules and the slither.io tuning directly, with no browser; `e2e/arena.test.mjs` boots the arena server on 8199 and Vite on 8198 (`e2e/helpers.mjs`), then checks the trail, a shared world across two tabs, reload resume, a server-replacement hop, the offline fallback, a 4x CPU-throttled phone frame rate, and the status endpoint. Run it before touching netcode.

`npm test` currently fails 16 script tests on a fresh checkout because they read `.grok/skills/*` files that only exist in the sandbox. That is the baseline, not a regression signal. `npm run lint` has one pre-existing error in `src/lib/app-data/client.server.ts`.

Built-output preview: `npm run preview:restart` serves the last build on `127.0.0.1:8081`. `scripts/preview.mjs` finds the port owner via `/proc`, so it is Linux only. `scripts/browser-smoke.mjs` (Playwright) only accepts output paths under `/workspace`, so it is sandbox only as written. Playwright browsers may need `npx playwright install chromium-headless-shell` once. `window.__coil` on a running page exposes live debug counters (mode, instance, rtt, points, foods, deaths, fps) for headless checks.

`src/routeTree.gen.ts` is generated by the TanStack router plugin on dev/build and is gitignored. If typecheck complains it is missing, run `npm run dev` or `npm run build` once.

## Deploying the server

The server is its own Vercel project, `agencoil-server`, linked from the repo root (`.vercel/project.json`) with the project's root directory set to `game-server` and source files outside the root included, so the build can reach `src/game/`. It is connected to the GitHub repo, so a push to `main` deploys it. The project's ignored-build-step command is `git diff --quiet HEAD^ HEAD -- . ../src/game`; it runs inside the `game-server` root directory, so paths are relative to it, and a commit touching neither `game-server/` nor `src/game/` is skipped. `vercel deploy --prod --yes` from the repo root deploys by hand. The frontend project `agencoil` deploys on every push and serves at `https://agencoil.vercel.app`. The production alias is `https://agencoil-server.vercel.app`, WebSocket at `/api/ws`, plain GET returns a status JSON including `stepMs` and the `hot` death cells. A second project, `agencoil`, deploys the frontend from the same repo root on push (Build Output from the nitro Vercel preset).

Hosting alternative: `game-server/Dockerfile` (build context is the repo root) and `fly.toml` deploy the same server to Fly.io as one always-on machine, which removes the connection cap and the idle reset. Nobody has run that yet; it needs `fly` credentials.

Abuse controls: `game-server/src/game-server.ts` caps connections per IP (4), connects per minute (20) and messages per second (60), and `src/names.ts` masks offensive names. The Vercel project has a firewall rate-limit rule on `/api/ws` (40 per minute per IP, deny), added through the firewall config API.

How it fits Vercel: WebSockets run on Fluid Compute functions. A connection is pinned to one instance and closed when the function hits `maxDuration` (800 s, set in `game-server/vercel.json`), and a reconnect may land on a different instance. The client reconnects automatically and presents a signed resume token; the same instance reattaches the held snake, a different instance rebuilds it with the same length near where it was. `GAME_SECRET` (project env) signs those tokens so they verify across instances. `DATABASE_URL` comes from the Neon marketplace resource `neon-chestnut-pebble` connected to the project and persists the daily leaderboard in a `agencoil_daily` table. The function region is pinned to `iad1`. The build command (`scripts/build-output.mjs`) writes a Build Output API v3 directory: one self-contained ESM function at `/api/ws` (esbuild bundles `ws` and `pg` in, with a `createRequire` banner for their CommonJS internals) plus `.vc-config.json` carrying `maxDuration` 800 and region `iad1`, and the status page under `static/`. This is deliberate: Vercel discovers `api/` functions from source before the build command runs, so a function generated at build time is never seen, and the Node builder emits ESM with extensionless relative imports that fail at runtime. The output directory works identically from git and from the CLI.

The frontend at snek.grok.me is deployed by the Grok platform, not from this repo's Vercel link. It connects to the production server URL baked into `defaultServerUrl()`.

## Architecture

### Routes

- `src/router.tsx` exports `getRouter()` (named export, required by the TanStack Start plugin).
- `src/routes/__root.tsx` is the document shell. It mounts `PreviewHostBridge` and `AuthProvider`.
- `src/routes/index.tsx` renders `CoilApp`. There are no API routes; the game talks to the separate server.

### Shared simulation (`src/game/`, imported by both client and server)

- `model.ts`: tuning constants, shared types (`Snake`, `Food`, `Camera`), banded skins, and the geometry helpers, which follow slither.io's client formulas in slither units: `scaleOf(mass)` is the body scale (1 at length 10, about 2 at 1000, capped at 4.86), width is `29 * scale`, parts are `2 + 106 * (scale - 1)` spaced `6 * scale` apart, length is parts times spacing, speed is `(5.39 + 0.4 * scale) * 31.25` units/s (`14 + 0.4 * scale` boosting, so boost is about 2.5x), turn rate is `4.125 * (0.13 + 0.87 * ((7 - scale) / 6)^2)` rad/s so the turning circle stays between one and two widths, zoom runs 0.9 to 0.48, boost sheds a constant 15 length/s as six pellets/s, and boosting needs length above 11. Keep these formulas together; the world, bots, renderer and client prediction all read them. `Food.k` is the orb kind: 0 natural, 1 boost trail, 2 remains of a dead snake, 3 chase orb. `Snake.bands` carries a custom skin, `Snake.temper` a bot personality.
- `world.ts`: the arena. Three uses: offline (`playerId` steered by aim, bots when `host`), server (every player has a `PlayerInput` in `inputs`, bots run, all collisions judged), and client mirror (no stepping, just the entity store, the food grid keyed by cell, and the trail helpers). Snakes are path-history point lists whose last point is always the head; `recordTrail` commits a point once the head is one spacing from the previous committed point. Bots choose a goal every 0.2 s (flee, coil, hunt, eat, drift) and bend it toward open space every 0.08 s using a nine-heading clearance scan. Food has server-assigned ids (`foodById`).
- `protocol.ts`: the binary wire format (`Writer`/`Reader` over `DataView`, one-byte type tags, `C2S` and `S2C` tables). Snake entries are head-only unless `full`, which adds identity, skin bands and a subsampled body.

Collision rules match slither.io: your head touching any other body or head kills you (contact is judged at 95% of the summed radii, which is where the drawn discs visibly meet; `HIT_CONTACT` in `world.ts`). Collisions are lag compensated: each player's INPUT carries its view lag (interpolation buffer plus round trip, capped at `MAX_LAG_COMP` 350 ms on the server), and `resolveKills` judges that player against every other snake rewound by that much (`rewind` walks the head back along the body by the distance the snake actually travelled in that window, from a per-tick `travel` log, and ignores the body that did not exist yet; `tailThen` re-adds the stretch of tail that has since been trimmed, kept in `tailHist`), so what a player saw is what kills them. Bots have zero lag. The client's reported lag is the interpolation buffer plus RTT plus half a snapshot interval. `DEATH` carries the position where the server judged the death and the client snaps its own corpse there, so a death is drawn where it happened rather than a round trip further on. Full snake entries carry up to `MAX_NET_POINTS` (220) body points so a coiled body arrives faithful on first sight. `e2e/world.test.mjs` pins this down, both heads die on a head-on hit (kills are collected against the tick's starting state and applied together, so order does not matter), the rim kills without leaving remains, and remains are worth most of the dead snake's mass. Spawn protection (`invuln`, 1.6 s) is two-way: a protected snake neither dies nor kills.

### Client (`src/game/net.ts`, `engine.ts`, `render.ts`, `audio.ts`)

- `net.ts`: `NetSession` owns the mirror `World`. Reconciliation is sequence-acknowledged: every INPUT carries a sequence number and the predicted head is recorded per sequence; the server echoes the last applied sequence in an ACK message before each snapshot, and the client compares the server head with what it had predicted at that same input, so the measured error is real prediction error, free of latency (about 4 units on average at 90 ms RTT, measured). The error is folded into an offset that bleeds in over a second; only errors over 140 units are applied at once. Snapshots run at 30 Hz. Interpolation delay for other snakes is 1.2x the worst snapshot gap seen in the last six seconds, bounded 80 to 220 ms (measured 80 ms on production), because every millisecond of that buffer is time skew between your predicted head and where the server actually judges other bodies. Eating is predicted locally and confirmed by FOOD_DEL. There is deliberately no client-side collision freeze: it produced worse artefacts than a few frames of overlap. `diag` on the session (exposed as `__coil.diag`) carries these measurements. Other snakes are interpolated `INTERP_DELAY` ms behind receipt time and their bodies are grown with `recordTrail` from the interpolated head, so only heads travel over the wire after the first full entry. Your own snake is predicted from the aim with `steerToward`, `moveHead`, `recordTrail`, then eased toward the server's extrapolated position (snap if the error exceeds 140 units). Food arrives as add/remove deltas for the area on screen; chase orb positions ride in every snapshot. Reconnect uses backoff, sends the last resume token, and flips to `offline` after 6 s of failure; the token also lives in `sessionStorage` so a reload resumes.
- `engine.ts`: `CoilEngine` renders whichever world is live. Steering is slither-style: the cursor gives a direction from the head (`aimScreen`, refreshed every tick in `refreshAim`), not a world point, so a still mouse holds a straight line; the camera sits on the head with no lead; it also owns the touch joystick (`setControls("stick")`), spectating a leaderboard snake after death (`watch(nid)`, positions ride in the STATS board), and starts the ambient pad in `audio.ts` on Play. (`net.world` when online, else a lazily built local bot arena), owns input (mouse or WASD aim, click, space or shift to boost, wheel zoom, touch drag steers without boosting), one simulation step per displayed frame by real elapsed time (clamped to 50 ms; every dt consumer is frame-rate independent, and inputs are throttled to 30 Hz), camera with lead and boost zoom pulse, the death pop animation, kill streak notices, and HUD state published through `subscribe()`. Phases are `menu`, `play`, `dead`. If the server does not spawn you within 4 s of Play it starts a local game.
- `render.ts` and `audio.ts`: Canvas 2D drawing (`Renderer`, `desiredZoom`) and a WebAudio synth (`GameAudio`). Bodies are shaded disc sprites placed by distance walked along the path, so a subsampled remote body looks the same as a local one. Skins come from `bandsOf`/`fillOf`, which honour custom bands. The background is a hex tile used as a canvas pattern.

Phones: `src/styles.css` pins the body and disables overscroll, selection and long-press callouts; the viewport meta blocks pinch zoom; the nickname input is 16 px so iOS does not zoom on focus. On touch devices the first finger steers and any second finger boosts (`boostFingers` in the engine), the lightning button also boosts, a fullscreen toggle appears where supported, Android gets haptics on kills and death, and the canvas minimap moves to the top-right under the notch using safe-area insets measured from a probe element and passed through `engine.setInsets`. WebKit cannot run on this machine (missing `libavif16`), so iPhone checks use Chromium with the iPhone device descriptor.

`src/components/coil-app.tsx` is the whole UI: menu with skin picker (skins 12 to 15 unlock at best length 120, 300, 600 and 1200, checked client-side only), a custom band builder, a steering toggle on touch devices, HUD (length, rank, kills, arena and daily leaderboard tabs, connection badge), the touch boost button, and the death card with a share button. Nickname, skin, custom bands and mute persist in `localStorage` under `agencoil-*` keys.

### Retention systems (v2 protocol)

Clients that append a device key to HELLO are "v2" and get extra messages; the older client still deployed on grok.me is served the original ones (`STATS` instead of `STATS2`, no `ACK`/`PROFILE`/`NEAR`/`EVENT`/`NOTICE`).

- Profiles: `game-server/src/profiles.ts` keeps best length, kills, games, longest life and an unlock bitmask per device key (`localStorage` `agencoil-device`), in memory and in the `agencoil_profiles` table when `DATABASE_URL` is set. Sent as `PROFILE` on spawn and after each death; all-time rank is a count query.
- Challenges: `src/game/challenges.ts` picks three per UTC day from a pool (seeded, deterministic), each unlocking a cosmetic bit; progress is folded in at the end of a life (`LifeStats`) and sent as `CHALLENGES`.
- Cosmetics: boost trails (`TRAILS`) and death effects (`DEATH_FX`). The trail rides in the high nibble of the wire's skin byte (`packSkin`/`unpackSkin`) so old clients keep working; the death effect only affects the local particle burst. The server validates both against the profile's unlocks.
- Near misses: `World.resolveNearMisses` fires once per other snake per `NEAR_COOLDOWN` when a player's head passes inside `NEAR_FACTOR` of the summed radii without touching; the server pays a small bonus that grows with the combo and sends `NEAR`.
- Bounties: the top three snakes over `BOUNTY_MIN_MASS` carry `mass * BOUNTY_RATE`; the killer gets 30% of it directly (capped) and everyone gets a `NOTICE`.
- Comeback: after death the server offers (`NOTICE` kind 3) one respawn per connection within `COMEBACK_WINDOW_MS` that keeps `COMEBACK_KEEP` of the lost length; the client requests it with the last byte of a v2 `SPAWN`.
- Parties: `?with=CODE` (or the invite button) sets a party code sent in HELLO; new members spawn near a live member.
- Arena events: every `SWARM_EVERY_S` the server drops `SWARM_ORBS` golden orbs (`Food.k` 4) at an open point and broadcasts `EVENT`; the client shows a banner and a minimap marker.
- Kill cam: the engine holds a 700 ms beat after death (particles at 0.35x, zoom in 1.25x) before the death card appears.
- Leaderboard page: `src/routes/top.tsx` fetches `GET <server>?top=alltime|weekly` (JSON, 30 s cache) from the game server; `ProfileStore.top` reads the profiles table (or memory) and excludes flagged accounts. Profiles also store the last look (`skin`, `bands`) for the stripe, the ISO-week best, and where the all-time best run ended.
- Spectating from the menu: while online, the menu camera follows the current leader (`stats.board[0]`), which the server streams because the client sends its view even when not playing.
- Skill-based spawn: a fresh spawn with all-time best 500 or more is placed 700 to 1200 units from one of the top five snakes; under 100 it goes to the quietest of eight sampled open points; a party overrides both.
- Weekly skin: `weeklySkinFor(isoWeek())` picks one of `WEEKLY_SKINS`; finishing `WEEKLY_GOAL` (3) daily challenges in a week adds the week to the profile's `earned` list. It is sent as custom bands, so the lock is a menu convenience, not a server rule.
- Ghost: `PROFILE` carries `bestX`/`bestY`; the renderer draws a faint ring and label there and a dot on the minimap.
- Anti-bot: `fingerprint` in the server keeps per-client input timing and heading statistics over 1800 inputs; a coefficient of variation under 1% with a heading that almost never or always changes flags the profile (`flagged`), which only removes it from the leaderboard page.
- Music moods: `GameAudio.setMood` glides the pad root and filter between calm, bright (length 200+) and heavy (1500+).
- First life: when the profile has zero games the server also spawns a tiny timid bot 420 units ahead (`spawnHelperBot`), and the engine shows timed hints (`hint()`, keyed on `agencoil-played` in localStorage until a profile arrives) plus a "first blood" feed line on the first kill. The death card adds "you beat N. one more?".
- Streaks: `ProfileStore.touchStreak` runs on the first life of a UTC day. A one-day gap is bridged by a banked freeze (one freeze per `FREEZE_EVERY_GAMES` games, max one held); otherwise the streak restarts. `STREAK_MILESTONES` unlock cosmetics at 3, 7, 14 and 30 days (bits 32, 64, 128, 256).
- Leagues: `leagueOf(weekBest)` maps the ISO-week best to Bronze, Silver, Gold, Platinum, Diamond (`LEAGUES`). The week roll in `rollDay` stores the finished tier in `prevTier` (1-based, 0 = none) so the menu can say where last week ended. The `/top` weekly tab labels rows with their league.
- Evolution level: `levelOf(eaten)` is `floor(sqrt(eaten / 300))`, where `eaten` is lifetime growth beyond the starting length. The client appends `?v=2` to the socket URL; the server records that as `proto` before `WELCOME` (which echoes it as a trailing byte) and writes the level as one extra byte after each full snake entry only for `proto` 2 connections. It must not key on the later device-key `v2` flag, which flips mid-connection and misaligned early snapshots; the renderer prefixes names with `LvN` and draws dorsal dots from level 5, fins from 10 and a gold halo from 20.
- Titles: `titleOf` picks Bounty Hunter (3 bounties), Untouchable (200 near misses), Hunter (50 kills) or Survivor (600 s longest life) from the lifetime totals `bountyTotal`, `nearTotal`, `kills`, `survive`.
- Landmarks: `LANDMARKS` in `model.ts` names five fixed places (the core, two rings, two shards); the renderer draws them in world space and on the minimap, and `startSwarm` rotates swarm events through them (`landmarkNear` gives the banner its name).
- Skin textures: `Skin.style` ("scales" or "stripes") is baked into the segment sprite (`makeSegmentSprite`, cache key `style|color`); custom bands have no texture. Level 20 and above gets `drawShimmer`, a bright pulse travelling down the body.
- Feel: a kill adds camera trauma and a 250 ms hit stop (`hitStopUntil`: effects at 0.35x and a 5% zoom); the head sprite squashes along the heading for 220 ms after a boost starts (`boostSince` in the renderer).
- Reactive audio: `GameAudio.eat` climbs a pentatonic scale with the combo, `setIntensity` opens the pad filter with arena rank, and the heartbeat also plays while a bigger head is within two of your lengths.
- Death replay and rematch: `recordReplay` keeps six seconds of nearby snake paths at 10 Hz (`ReplayFrame`); on death it is frozen into `hud.replay` and `ReplayView` loops it on the death card. If the killer is still alive, `hud.rematch` offers `respawn(false, true)`, which sends the killer's nid as a trailing u16 on the v2 `SPAWN` and the server places the spawn 600 to 900 units from it, facing it (`spawnNearSnake`).
- Dynamic resolution: `adaptQuality` lowers `qualityScale` (1, 0.8, 0.65, multiplied into `dpr`) after two seconds under 45 fps and raises it after six seconds over 57. Food orbs under 2.5 screen pixels are batched into one path per colour.
- Afterlife (wisp): when a proto-2 client's snake dies the server keeps a `wisp` on the client record for `WISP_SECS`: it moves at `WISP_SPEED` (or `WISP_BOOST`) in the INPUT angle, eats natural, boost and remains orbs anywhere inside a `WISP_REACH` (70 unit) halo into `bank` (capped at `WISP_BANK_MAX`, 150), and sends `S2C.WISP` (x, y, bank u16, secsLeft u8) every snapshot; secsLeft 0 ends it, which happens at the timeout or the moment the bank is full. A full bank respawns at once with no death card. The next `SPAWN` starts at `START_MASS + bank`. The client enters phase `wisp` after the death beat, predicts the wisp from the aim, draws it (`drawWisp`), and Enter or the "spawn now" button ends it. `COMEBACK_WINDOW_MS` is 30 s so the comeback survives a full wisp.
- Adaptive bots: `Snake.rookie` (all-time best under 100, or two consecutive lives under 20 s, tracked as `Client.rough`) makes bots skip coiling them, hunt them only a quarter of the time and never with a boost. A rough start also respawns in the quiet corner with a helper bot.
- Boss Hour: at UTC minute `BOSS_MINUTE` the server spawns `World.spawnBoss` (mass `BOSS_MASS`, `BOSS_HP` hit points, patrols landmarks at 0.55 speed, never boosts) near a landmark for `BOSS_DURATION_S`. In `resolveKills` a head touching the boss body is a `contact(..., false)` that becomes `bossHit`: once per second per attacker it removes a hit point, drops three remains at the cut and feeds the attacker `BOSS_HIT_MASS`; the boss head still kills. `World.bossHits` is drained by `stepBoss`, which counts hits per client, gives the final cutter `Profile.crownUntil` (an hour; `SNAKE_CROWN` flag on the wire, drawn as a crown) and opens a chest for everyone who hit it. The `STATS2` tail carries boss hp percent (255 = none) and position; the renderer draws a red glow and a hit-point bar (`drawBossMarks`).
- Quest chain and chests: `recordLife` only folds a life into the first unfinished daily challenge; finishing the third opens a chest. `openChest` adds a shard (profiles start with one); `CHEST_SHARDS` shards unlock the next bit in `COSMETIC_ORDER` the profile lacks. `PROFILE` tail append: shards u8, crew str, crownSecs u16.
- Crews: `C2S.CREW` sets a 2 to 4 character tag (validated with `cleanName`) on the profile; the snake's wire name becomes `[TAG] name`; `/top?top=crew` sums members' week bests (`ProfileStore.topCrews`).
- Near-win and goal gradient: `dieLocal` sets `nearWin` when the run ended within 15% of the best or within two ranks of first (the card says "so close" and "Run it back"); `goalNow` picks the closest of the next skin unlock, the active quest step and a beat target for the HUD bar.
- Shareable loops: `?beat=N&by=NAME` in the URL sets `hud.beat`; crossing it posts a feed line. The death card offers a "beat my run" link and an animated GIF of the replay (`src/lib/gif.ts`, a small GIF89a encoder over a fixed 6x6x6 palette; `replayToGif` in `src/lib/replay.ts`).
- Emotes: keys 1 to 4 (or the four buttons on touch) send `C2S.EMOTE`; the server rate-limits to one per 1.5 s and rebroadcasts `S2C.EMOTE` to v2 clients that know the snake; the renderer floats the glyph above the head for 2.2 s.
- Party totals: the v2 `STATS2` tail lists live party members with their lengths, and the HUD shows the combined length.
- Hourly modes: `modeNow(now)` is active for the first `MODE_MINUTES` (15) of every UTC hour, cycling through `MODES` (double remains, hunger, tiny arena spawns). The server applies them each second through `World.remainsMult` and `hunger` (`HUNGER_RATE`), and disables comeback during "tiny". The mode id and both countdowns ride at the end of `STATS2`; the menu shows the next event and the HUD shows the remaining time.
- Seasons: `seasonOf(now)` counts six-week seasons from `Date.UTC(2026, 8, 7)`. Profiles keep `season` and `seasonBest`, reset on roll; `/top?top=season` lists the season board.

`PROFILE` tail order (v2, appended after `weekBest`): streak u16, freezes u8, prevTier u8, eaten u32, nearTotal u32, bountyTotal u16, seasonBest u32, season u16, shards u8, crew str, crownSecs u16. `STATS2` tail: party count u8 then (name, length u32) pairs, mode id u8, secsLeft u16, secsToNext u16, boss hp u8 (255 none), boss x f32, boss y f32. Both are read only when enough bytes remain, so a newer client tolerates an older server.

### Server (`game-server/`)

- `src/game-server.ts`: `GameServer` wraps one `World`, ticks at `SERVER_TICK_HZ` (40), snapshots at `SNAPSHOT_HZ` (30) and syncs food at `FOOD_SYNC_HZ` (10). Per client it tracks the view rect from the last input, the set of snakes it has been sent (`known`, so the first sighting is `full`), and the set of food ids it holds (`sentFood`, diffed against the cells covering the view). Deaths broadcast to clients that knew the snake; eats go only to the eater. Snake-on-snake deaths feed a coarse heat map (`hotKey`, 400-unit cells); cells with three or more deaths in ten minutes go into `World.hot`, which `findSpawn` avoids. A disconnect holds the snake for `DISCONNECT_GRACE_MS` before killing it. A resume token is single-use per instance (`usedTokens`); presenting one while another socket still owns the snake transfers ownership rather than building a second copy; a `SPAWN` from a client whose snake is alive ends that life first. The loop pauses when no client has been connected for 30 s.
- Load protection: `MAX_PLAYERS_PER_INSTANCE` (60, measured against Vercel CPU) closes new sockets with `S2C.FULL` plus a retry delay; the client retries after that delay. Bots scale down as players arrive (`max(SERVER_BOTS_MIN, SERVER_BOTS - 0.6 * players)`), snapshots drop to 20 Hz when a step exceeds 6 ms, and snakes outside a client's view plus a 20% margin are sent every other snapshot. Loopback is exempt from the per-IP caps so load tests can run locally. The status JSON reports `capacity` and `loopMs`.
- `src/daily.ts`: best length per name for the current UTC day, in memory, flushed to Postgres every 5 s when `DATABASE_URL` is set.
- `src/vercel-entry.ts` exports an `http.Server` (what Vercel's WebSocket support expects); `dev.ts` listens on `PORT` for local runs.

### Template invariants

These come from `AGENTS.md` and still hold for this repo:

- Auth is OFF for this app. There is no login route, and nothing imports `authMiddleware` or `requireUserId`. `src/lib/auth/`, `src/lib/app-data/` and `src/lib/db.ts` are pre-wired template code kept for the platform, not game code.
- Keep `vite.config.ts` as is: dev on `0.0.0.0:8080`, preview on `127.0.0.1:8081`, the build-only nitro plugin with `serverDir: "./server"`, `authPopupPlugin()` before `tanstackStart()`, and `grokPwaPlugin()`.
- Do not delete or rewrite `public/__grok/`, `server/`, or `scripts/grok-pwa-*`. App server routes would go in `src/routes/`, never in `server/`.
- Never put `og:*` or `twitter:card` meta in `__root.tsx`; the PWA injector owns those. OG identity lives in `src/lib/og/site.json` and `public/og.jpg`.
- Keep `<PreviewHostBridge />` and `<AuthProvider>` in the root shell.
- Never create a `.env` file. Only `VITE_`-prefixed vars reach the browser.
- The frontend deploy target is Vercel via the Grok platform. Avoid runtime filesystem writes and server-only Node APIs at module import time.

## Styling

Tailwind v4. Design tokens are declared in `@theme` in `src/styles.css` (`bg`, `surface`, `elevated`, `fg`, `muted`, `subtle`, `line`, `accent`, `accent-fg`, `danger`, font `Outfit`). Use those token classes (`bg-surface`, `text-muted`, `border-line`) rather than raw palette colors so the UI stays coherent with the canvas art. Overlay elements that must receive pointer events while the game runs carry `data-ui`; the engine ignores pointer events originating there.
